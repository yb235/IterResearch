# 文献：这类问题在研究里是怎么建模的

问题的形态：一家增长极快的公司，审计过的季度收入只有 7–10 个；公司说法和媒体泄露有噪声、口径不一；另类数据（下载量、支出面板）频率高但历史短。下面是从 alphaXiv 检索到、和这个形态直接相关的论文，每篇只记对本项目有用的结论。

## 1. 混合频率的状态空间 / 动态因子模型：主干方法

[Tracking the economy at high frequency](https://www.alphaxiv.org/abs/2507.07450)（arXiv 2507.07450）

- **做法**：周度潜在因子加上季度、月度变量，季度值通过跨期加总约束和周度状态联系起来（Mariano–Murasawa 式）。用 Kalman 滤波和模拟平滑器做贝叶斯估计（Gibbs），专门面向官方数据稀疏、发布时间不同步的环境（p.1, p.11–14）。
- **允许领先/滞后载荷**：每个指标可以载荷在因子的滞后项上（“dynamic heterogeneity”），并在规格网格上比较（p.10, p.12）。
- **加入随机波动率**：因子和特异项的方差随时间变化（p.11）。
- **用 pseudo-week 代替日历周**：保证每月 4 周、每季 12 周，避免日历周带来的不规则缺失和矩阵尺寸变化（p.6–7）。

**对本项目**：我们的状态空间模型属于这一类，方向是对的。可以借鉴三点：
- 用随机波动率处理 Q3 那样的关系突变；
- 用完整的贝叶斯后验（模拟平滑器），而不是代入点估计。这样区间会包含参数不确定性，正好对应我们样本外区间偏窄 1.5–1.7 倍的问题；
- 多个指标共用一个因子，而不是各自一条漂移截距。

## 2. 把训练标签“插值出来”：文献明确避免

[Nowcasting R&D Expenditures: A Machine Learning Approach](https://www.alphaxiv.org/abs/2407.11765)（arXiv 2407.11765）

- **做法和你的想法同构，但顺序相反**：
  - 第一步：只在真实的低频数字（年度 R&D）上做监督学习；
  - 第二步：用学到的弹性，把年度值分摊成月度值（p.1–2）。
- **插值只用于特征，不用于目标**：缺失的年度值用线性插值补，但“插值值只用于滞后的预测变量，不用于目标变量”（p.7）。
- **跨国家合并样本**：8 个国家一起训练，用一点偏差换来方差的大幅下降（p.6）。
- **月度插值无法验证**：作者承认，没有真实值，无法判断哪种时间分解方法更好（p.15）。

**对本项目**：这和我们的回测结论一致。插值标签不增加独立信息，验证只能在真实锚点上做。

## 3. 指标多、低频样本少：正则化的 MIDAS

[Factor-augmented sparse MIDAS regressions](https://www.alphaxiv.org/abs/2306.13362)（arXiv 2306.13362）

- **做法**：高频指标经 MIDAS 加权后，直接对低频目标回归，不需要编造中间标签。正则化用 sparse-group LASSO，再加上 PCA 提取的公共因子（p.2–3, p.10）。
- **调参**：按时间分块做 5 折交叉验证（p.10）。
- **结论**：稳定时期，稀疏模型就够了；动荡时期，公共因子的作用很大（p.4, p.21–22）。

**对本项目**：这是“ML 加先行指标”的规范做法。但它依赖几十年的季度样本，我们只有 7–10 个季度，要等跨公司面板。

## 4. ML 在公司财务预测上有效的前提：跨公司合并

[Forecasting Company Fundamentals](https://www.alphaxiv.org/abs/2411.05791)（arXiv 2411.05791）

- **样本**：2,527 家公司，2009–2023 年季度数据，比较 24 个模型（p.8）。
- **点预测**：超越简单基线很难（p.16）。
- **概率预测**：在多家公司上训练的全局深度模型最好，方差更校准（p.11, p.16）。
- **预训练时间序列模型**：Chronos 在这里表现差（p.26）。

[Predicting Company Growth using Scaling Theory informed ML](https://www.alphaxiv.org/abs/2410.17587)（arXiv 2410.17587）

- **做法**：机制性的趋势模型，加上 ML 拟合残差（“混合”）。用了 31,553 家公司的数据（p.1）。
- **效果**：比纯机制模型准 23%，比纯 ML 准 5%（p.17）。小公司、高波动公司从 ML 残差中受益最多（p.11）。

**对本项目**：ML 的收益来自上万条序列。单家公司、十几个标签，复杂 ML 必然过拟合。“机制模型做主干、ML 修正残差”和我们回测里“状态空间 + ridge 平均最好（0.087）”是同一个方向。

## 5. 历史很短时：让 LLM 读另类数据

[Making Alternative Data Work: Context-Augmented LLMs for Financial Forecasting](https://www.alphaxiv.org/abs/2609.11607)（arXiv 2609.11607，2026 年 9 月）

- **为什么监督模型难做**：商业另类数据（刷卡支出、网页流量、到店流量、Kalshi 的公司 KPI 预测市场）历史短、覆盖窄、渠道异质，监督模型很难训练（p.1–2）。
- **做法**：一个代理先判断某个数据渠道对这家公司是否相关，另一个代理读财务历史、另类数据和上一次财报电话会，直接输出收入预测（p.2, p.4）。
- **结果**：LLM 在上下文中推理的误差，远低于用前 6 个季度训练的 OLS 和 GBT。以刷卡数据为例，FVU 为 0.122，OLS 为 0.428，GBT 为 0.453（p.5–7）。在多数事件上胜过分析师一致预期（p.7）。
- **先筛选相关渠道**：筛选后，信号和收入意外的相关性从 0.238 升到 0.281（p.6–7）。
- **防止泄漏**：只评估模型知识截止日期之后公布的季度（p.5）。

**对本项目**：
- **这是最有希望的“ML”方向**：让 LLM 同时读指标序列、公司披露和产品发布时间线，直接给出估计。
- **泄漏风险**：LLM 很可能在训练数据里见过 Anthropic 的真实数字，必须只评估知识截止日之后的数据点。
- **新数据源**：Kalshi 这类预测市场可能有 Anthropic 收入或 run-rate 的合约，可以作为一个新渠道。

## 对本项目的建议（按优先级）

1. **保留状态空间做主干，升级为完整贝叶斯**：用模拟平滑器 / Gibbs 采样参数后验，替代现在的点估计加网格；指标改成共享因子加领先/滞后载荷；加入随机波动率。目标是修正样本外区间偏窄的问题。
2. **ML 只做残差修正，不再用插值目标训练**（第 2、4 节）。
3. **让 LLM 读另类数据**（第 5 节）：需要 LLM API key，并严格只评估知识截止日之后的目标。
4. **跨公司面板**（第 3、4 节）：需要 SEC 数据访问，要用到一个联系邮箱。
5. **预测市场数据**（Kalshi）：需要放行对应主机。
